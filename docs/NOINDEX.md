# Site-wide noindex

**Every page on this build carries `noindex, nofollow`.** That is deliberate
and it stays that way until the site is finished.

## How it works

One switch, `PUBLIC_ALLOW_INDEXING`, read in `src/lib/site.ts`.

| State | Meaning |
|---|---|
| unset, or anything but `true` | **noindex** on every page. The default. |
| `true` | normal indexing, per `docs/SEO-SPEC.md` section 3.1 |

The default is fail-safe on purpose. Forgetting to switch it on costs traffic
you never had; forgetting to switch it off would leak a half-built site into
search results, and getting pages back out of the index is slow.

Three things follow the switch, so they cannot disagree with each other:

1. **`<meta name="robots">`** in `src/layouts/BaseLayout.astro`, on every page.
2. **`robots.txt`**, generated by `src/pages/robots.txt.ts`.
3. **The sitemap**, which is not generated at all while noindexed. Publishing
   a sitemap of noindexed URLs is a contradictory signal.

A per-page `noindex` prop still applies when the switch is on. The 404 page,
`/thankyou/` and paginated archives past page 1 are noindex permanently.

## Why robots.txt still allows crawling

It would seem safer to serve `Disallow: /`. It is not.

`Disallow` stops a crawler fetching the page, so it never reads the `noindex`.
A URL that gets linked from anywhere can still end up indexed on the strength
of the link alone, showing as a bare URL with no snippet. Letting crawlers in
to read the `noindex` is what actually keeps pages out of the index.

So while pre-launch: crawling allowed, indexing refused, no sitemap.

## Belt and braces

The meta tag covers HTML. It does not cover PDFs, images or anything else a
crawler might reach directly. Add this to the nginx directives for as long as
the site is pre-launch, and remove it in the same change that flips the switch:

```nginx
# PRE-LAUNCH ONLY. Remove when PUBLIC_ALLOW_INDEXING=true.
add_header X-Robots-Tag "noindex, nofollow" always;
```

If the staging site is reachable at a public hostname, HTTP basic auth in
Plesk is stronger than any of this and worth having as well.

## Going live

This is a launch-checklist step, not a code change:

1. Set `PUBLIC_ALLOW_INDEXING=true` in the deploy workflow environment.
1a. Set `PUBLIC_ENABLE_TRACKING=true` in the same place, at the same time.
   Analytics and the Gleap widget are off by default for the same fail-safe
   reason as indexing: until then every build, preview and local run would
   post pageviews into the client's real property. See
   `src/components/ThirdParty.astro`, which also records what is wrong with
   the tags that were supplied.
2. Remove the `X-Robots-Tag` nginx directive above.
3. Remove basic auth, if it was set.
4. Deploy, then **verify from outside** with curl, not DevTools:
   ```bash
   curl -s https://www.roarsinc.com/ | grep -E 'name="robots"|rel="canonical"'
   curl -s https://www.roarsinc.com/robots.txt
   curl -s https://www.roarsinc.com/ | grep -c 'google-analytics.com'
   ```
   Expect `index,follow,max-snippet:-1,...` and a `Sitemap:` line.
5. Only then submit the sitemap in Search Console.

Doing step 5 before step 4 confirms is how a site gets crawled while still
telling Google not to index it.
